## 常用命令

```bash
# 查一台车的记录位置
python tools/index6.py "Ferrari LaFerrari"

# 看一台车的物理档案 / 对比几台
python tools/car.py "McLaren Senna" "Jesko"

# 整车替换（外观+物理+几何，只留受体身份），一次多台，微调参数作用于前面最近的 --swap
#   可用微调: --top-speed --accel --grip --handling(操控76/77) --steer(锐度19/21)
#            --downforce(30/31) --cg --susp --track-f
#            --nitro-boost(加成倍率) --nitro-drain(消耗倍率) --purple-drain(只动紫喷)
#   开关:     --keep-look 保壳(只换物理+几何,外观/引擎声留受体)  自体强化写 "A>A"
python tools/carswap.py --swap "供体>受体" [微调...] [--keep-look] --swap ... --apply

# 车队日常管理（推荐）：配置存在 fleet-plan.json，增删改查不用再抄长命令
python tools/fleet.py                     # 车队清单（20 台现状一览）
python tools/fleet.py add "Aston Martin Valkyre>福特GT" --keep-look \
    --top-speed 287 --steer 62000 --handling 0.9 --nitro-boost 1.5   # 加新车
python tools/fleet.py set "福特GT" --top-speed 300                   # 只动写到的项
python tools/fleet.py donor "福特GT" "Mercedes_AMG_One"              # 换供体，微调保留
python tools/fleet.py remove "福特GT"
python tools/fleet.py build      # 按计划文件从原始库全量重算 -> tuned-carswap(--apply)
python tools/fleet.py install    # 回封+签名+装机（等价 ./tools/build.sh）


# 只换物理，不动外观
python tools/transplant.py --from "..." --to "..." --with-chassis --maxed --apply

# 回封 + 签名 + 安装（一条龙）。crashtest 已停用（会杀游戏打断实测），
# 需要崩溃复现时手动跑 ./tools/crashtest.sh <标签>
./tools/build.sh <标签> --tuned <目录> --files CarPhysics.gdb CarChassis.gdb CarDef.gdb

# HUD 换算
python tools/hud.py add --car "..." --physical 260 --hud 350 --condition "比赛实测"
python tools/hud.py fit

# 重新生成全库统计表（换版本后必跑）
python tools/fleetstats.py > 02-字段表/fleet-stats.md
```

**默认行为**：满改锁（18 对升级值钉满级端）默认开启，任何星级输出同一套满级性能
——这是车队标准，`--no-maxed` 才会关。面板（business 库）永远不动。

## 常见陷阱（都真踩过）

### 1. 别手写「全库最高/最低」

已经错过三次，而且错数被后续分析引用、推出了错误结论：

| 手写说法 | 6.0.0k 实际 |
|---|---|
| 转向锐度 56500 是全库最高 | **98,900**（Devel Sixteen），56500 只到 90 百分位 |
| 抓地 1.153 是全库最高 | **1.300**（NIO EP9） |
| 银电蓝喷消耗 14 是全库最低 | **9.00**（保时捷 911 GT3 RS） |

**一律引用 [`02-字段表/fleet-stats.md`](02-字段表/fleet-stats.md)**，
它由 `tools/fleetstats.py` 生成、带版本戳、自动剔除开发用参考车与非玩家载具。
换版本就重跑一遍。

### 2. 报「半径变化」必须说清基准

半径代理 `v² / 抓地`，两个基准差很远：

| | vs 受体原厂 | vs 供体原厂 |
|---|---:|---:|
| 宝马 Z4 ← AMG One | **0.964×** | 0.850× |

**车主的体感基准是受体原厂**（他开的就是这台车）。
只报「vs 供体原厂 ×0.850」会造成「15% 达标」的错觉。
`carswap.py` 现在两个都打印，受体那个标了「体感基准」。

### 3. 跨记录引用只能用 key，不能用偏移

改指向（`alias`）存的是偏移量，本库一重排就成野指针 → 开屏闪退。
见 [`01-代码层/07`](01-代码层/07-底盘改指向的陷阱.md)。

### 4. 判别分析前必须按记录长度过滤

电动车记录 452B/468B，**字段下标整体偏移**。混进 428B 队列做统计，
读到的是别的槽，会算出假信号（真踩过：一次 3125σ 的假分离）。

### 5. 别用「与别的字段相关性」判定语义

`idx30/31` 与抓地相关只有 −0.13，我据此否掉了它；
实际它就是下压力，只是**下压力本来就不该和抓地相关**。
判定语义要用**判别分析**：拿目标现象分组，看哪个字段能分开。
见 [`04-实测反馈/10`](04-实测反馈/10-下压力字段闭合.md)。

### 6. 算术能解释的，别叫机制背锅

半径没变小的原因是 `v²` 和抓地同速上涨，不是抬轮抬飘了前轮。
**先用正确基准把算术做完，再考虑机制。**
见 [`04-实测反馈/07` §7](04-实测反馈/07-抬轮吃掉抓地-半径的真实约束.md)。

### 7. 「进程还活着」不算验证

必须有阴性对照：已知能跑的版本走同一路径必须不崩。
见 [`01-代码层/05` §10](01-代码层/05-外观移植闪退诊断.md)。

### 8. 验证一个变量有没有用，一步跨到顶格值

锐度 +12%（65000）实测体感零变化，+70%（98900）立竿见影。
小步试探得出的"无效"结论只是噪声里的错觉。
见 [`04-实测反馈/11`](04-实测反馈/11-转向锐度定档-AB实验.md)。

### 9. 教程车 ≠ 主记录（同名多条）

Ferrari LaFerrari 有两条 physics 记录（主 0x20954 / #2 0x220EC），
**新手教程加载的是 #2**。改主记录教程毫无反应——
多记录车动手前先 `index6.py` 确认真的改对了那条。

### 10. 手搓 zip 替换 C: 类 asset = 开屏闪退

repack.py 会自动解密 manifest、同步 C:<size>、重加密并 round-trip 校验。
绕开它手写 zipfile 的产物**必崩在开屏**（CarDef 等启动必读资源的
尺寸与清单对不上）——2026-08-27 jmox 实验踩过，连崩三版装机。
规则：**替换 C: 类 asset 一律走 repack.py**；NC/NX 类（车模）manifest
无尺寸记录，zip 级后处理替换才是安全的。

### 11. 车库 UI 名 ≠ 库内名（会改错车）

车库卡片显示名走本地化层，和 CarDef 内部名可能是两台车的距离：
UI「CHALLENGER SRT8」在库里叫 **Dodge Challenger**（D 级，性能分上限 1405），
而 `Dodge Challenger 392 HEMI Scat Pack Shaker`（rank 2152）是**另一台车**。
2026-08-28 伊莫拉换皮改错目标，整晚「怎么改都没反应」就是这个。
**规则：动手前用 `index6.py` 解析名 + 面板性能分上限双重核对目标车。**

### 12. 单跑 carswap.py --apply = 全量重算，直接冲掉整个车队

carswap.py 每次从**原始库**重算输出，命令里没有的 swap 就不存在——没有增量模式。
2026-08-28 单喂一条 swap 直接落盘装机，20 台车队全部回到原厂。
**规则：加车/改车/回滚一律 `fleet.py add/set/donor/remove` → `build` → `install`，
fleet-plan.json 是车队唯一事实源；carswap.py 只作为 fleet.py 的底层构件调用。**

## 五条铁律

1. **HUD 数字只认比赛里实读的**，面板值另存、不参与拟合。见 `05-HUD实测库/README.md`。
2. **全库数字只认 `fleetstats.py` 生成的表**，不手写、不跨版本沿用。
3. **验证必须有阴性对照。** "进程还活着"不等于"改动生效了"——
   连续三次误判就是这么来的，见 `01-代码层/05` 第 10 节。
4. **满改锁默认开**：改装车一律 18 对升级值钉满级端（车队标准，
   见 [`04-实测反馈/12`](04-实测反馈/12-车队改装总账.md)），不许随星级插值。
5. **车队改动只走 `fleet.py`**（add/set/donor/remove → build → install），
   装机后交车主上屏验收。carswap.py 直接 --apply 会把计划外的车全部冲掉
   （2026-08-28 事故，见陷阱 12）。
