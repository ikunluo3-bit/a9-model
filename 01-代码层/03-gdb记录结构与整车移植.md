# gdb 记录结构 · 整车物理移植

---

## 1. 通用文件结构

`CarPhysics.gdb` / `CarChassis.gdb` / `CarDef.gdb` 是同一种容器：

```
[24B 文件头]  magic 0f6adee360a01c86 | u64 记录区起点(0x18) | u64 记录区终点
[记录体区]    各记录首尾相接，无对齐填充
[4B 填充]     全 0
[u32 条数]
[条数 × 32B 描述符]   key(u64)  off(u64)  size(u64)  tag(u64)
```

- 描述符顺序 == 记录偏移顺序
- 描述符表起始**不保证 4 字节对齐**（CarChassis 在 0xD493）——
  按 4 字节步长扫描会整表扫空，这是踩过的坑

| 库 | 记录数 | tag |
|---|---:|---|
| CarPhysics | 351（347 车 + 4 非车） | `0x83C70E66` |
| CarChassis | 350 | `0x924E4D88` |
| CarDef 车辆定义 | 351 | `0xA14668DB` |

## 2. 移植为什么成立

**记录体是纯数据，车辆身份只存在于描述符的 `key`。**

把 A 车的记录体原样写进 B 车的记录位置：

- `key` 不动 → CarDef 的引用不断
- 车库、图鉴、面板、联机校验读的是 business 库 → 一个字节没变
- 但物理引擎加载 B 时拿到的是 A 的全部参数 → **跑起来完全是 A**

尺寸不同也不阻塞：整库重排（重新计算所有 `off`、更新文件头的记录区终点）即可。
`transplant.py` 的空重建对两个库都**逐字节等于原文件**，重排逻辑已验证。

## 3. 移植的两个层次

| 层次 | 搬什么 | 效果 |
|---|---|---|
| 只搬 CarPhysics | 107 个性能槽 | 动力/抓地/转向/氮气全换，**车身几何保留** |
| 加搬 CarChassis | 质量 / 轮距 / 轴距 / 轮径 / 重心 | 连惯性与抬轮特性一起换，**真·同一台车** |

抬轮指数 = 抓地 × \|重心高\| ÷ 前轮距 —— 只搬物理时抓地变了、几何没变，
抬轮会按新抓地重算；两层都搬则完全复刻供体。

**示例（塞纳 → 宝马 Z4）**

| | Z4 原值 | 移植后 |
|---|---:|---:|
| 极速 | 218.5 | 268 |
| 抓地 | 0.580 | 0.785 |
| 转向锐度 | 26800 | 52500 |
| 操控 idx77 | 0.42 | **1.00** |
| 抬轮指数（只搬物理） | 0.0631 | 0.0854 |
| 抬轮指数（连几何搬） | 0.0631 | 0.0772 |

## 4. 车名关联的正确方法

CarDef 车辆定义记录头部是**固定布局**：

```
+0  u64  ?
+8  u64  ?
+16 u32  车名长度
+20      车名 (ASCII)
```

车名与 CarPhysics / CarChassis 的 key **在同一条记录内**。
按"记录内包含"关联，一次命中 351/351。

> **必须废弃的旧方法**：早期用"key 在 CarDef 中的位置 → 最近的前置车名"，
> 这是启发式，会被中间夹杂的其他串带偏。
> **它把 `0x1FBEC` 误判成 Ferrari LaFerrari，实际是 VLF Force V10。**
> 此前所有魔改方案都照这个偏移改了一台不相干的车。

> **UI 显示名 ≠ CarDef 内部名**（2026-08-28 踩坑）：车库卡片名走本地化层，
> 「CHALLENGER SRT8」在 CarDef 里叫 `Dodge Challenger`（D 级，性能分上限 1405），
> 而 `Dodge Challenger 392 HEMI Scat Pack Shaker`（rank 2152）是另一台车——
> 拿 UI 名去库里搜会搜不到或搜错。**定位目标车必须以 CarDef 解析名 +
> 性能分上限双重核对**（UI 名连 "srt8" 字样在库里都不存在）。

## 5. 库里的两台开发用参考车

| 名字 | 极速 | 抓地 | idx77 | 转向 |
|---|---:|---:|---:|---:|
| **Fastest Car** | 339.8 | 1.081 | 1.00 | 66667 |
| **Slowest Car** | 195.0 | 0.483 | 1.00 | 37000 |

Gameloft 自己留的上下界样本，**引擎必定认**。
`Fastest Car` 复用 LaFerrari 的底盘记录（chassis `0x42F2`）。
做极限移植时它比自造数值安全——不是我猜的边界，是官方标定的边界。

## 6. 工具

```bash
python tools/index6.py "Ferrari LaFerrari"                 # 查记录位置
python tools/transplant.py --list-donors                   # 供体榜
python tools/transplant.py --from "McLaren Senna" --to "BMW Z4 LCI E89" --with-chassis --maxed --apply
```

`transplant.py` 每次都做**回滚自检**：把改动撤回后必须逐字节等于原文件，
不通过就直接退出。
