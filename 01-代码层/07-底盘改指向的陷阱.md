# 底盘「描述符改指向」的陷阱：野指针闪退

**症状**：游戏开屏卡住然后闪退，`reason=5 (APP CRASH(NATIVE))`。

**根因**：改指向存的是**偏移量**，不是 key。

---

## 1. 怎么踩上的

整车替换里，受体底盘记录与供体尺寸不同时，早期用的是「描述符改指向」：

```python
alias(ch, 受体chassis_key, 供体记录.off, 供体记录.size)
```

好处是文件长度不变。**但它把供体记录的 `off` 硬写进了受体的描述符。**

一次替换两台车时：

```
科迈罗 <- 女武神     底盘尺寸不同 -> 改指向，写死「女武神记录在 0x64FB」
Z4     <- AMG One    要改重心 -> 必须复制记录体 -> 触发 CarChassis 整库重排
                     -> 所有记录偏移平移 -> 女武神记录不在 0x64FB 了
                     -> 科迈罗的描述符指向一段错位的字节 -> 开屏闪退
```

**单台车替换时不会暴露**：没有别的改动触发重排，偏移就没变过。
所以前面几版一直好好的，加上第二台车＋改几何的那一版才崩。

## 2. 修法

**底盘一律复制记录体，不再用改指向。**

```python
rep_ch[受体记录.off] = 供体记录体      # 尺寸不同也没关系，rebuild 会重排
```

原先用改指向是为了保持文件长度（Pegasus manifest 记着明文大小）。
`repack.py` 已支持同步改 manifest 里的 `C:<size>`（位数相同即可），
所以这个理由不成立了。

## 3. 通用教训

> **凡是跨记录引用，只能用 key，不能用偏移。**

CarDef 尾部那张 376,612B 依赖表就是正面例子 ——
它全按 key 引用，区内 47,076 个 u64 命中记录偏移 0 个，
所以重排 CarDef 记录区不会破坏它。

改指向（`alias`）现在只保留给**不会触发本库重排**的场合，
`transplant.py` 里还留着；`carswap.py` 已经完全不用它。
