# 认证浮点机制 · 抓地力完整链路

CN 5.9.0l / 590301，`libAsphalt9.so`。全部地址为模块内偏移。

---

## 1. Authenticated Float（反篡改浮点）

游戏的运行时物理值**不是裸 float**，每个占 **12 字节**（三份冗余）。

### 解码 `0x3535498`（返回 s0） / `0x3535510`（写入 x8）

```
v1 = [addr+0] ^ addr     ^ key1()      key1 = 0x35358b4
v2 = [addr+4] ^ (addr+4) ^ key2()      key2 = 0x3535920
v3 = [addr+8] ^ (addr+8) ^ key3()      key3 = 0x3535998
if not (v1 == v2 == v3):  bl 0x4aa4d48    ← 篡改陷阱
```

### 编码 `0x3535860` / `0x3535ef0`

结构与解码完全对称：`value ^ 存储地址 ^ key_i`，依次写三份。

### 三个 key

分别读全局 `0xa3db0b8` 等（带 guard byte 的懒初始化），
**进程启动时生成，无法离线预计算**。

> 这是"改 gdb 资源"优于"运行时改内存"的根本原因：
> 运行时改必须同时写三份、算对每份的存储地址、且拿到当前进程的三个 key，
> 少一样就触发 `0x4aa4d48`。

### 调用点规模

| | 数量 |
|---|---:|
| 解码调用点 | 386 |
| 编码调用点 | 122 |
| 可解析出偏移的解码点 | 363（93 个不同偏移） |
| 可解析出偏移的编码点 | 98（24 个不同偏移） |

字段访问常经由极简 thunk：`add x0, x0, #imm ; b <decoder>`，
全库共 9037 个此形状的 thunk。

## 3. 抓地力完整链路（`0x360deb4` tyre grip writer）

```
for each wheel:
    if !接地[wheel+0x1B8]:                      # 0x584bb74: ldrb [x0+0x98]
        continue                                # 不接地 → 整个轮子跳过
    material = [wheel+0x1A4] >> 16              # 0x58684b4 拆包 u32 的高 16 位
    (g_lo, g_hi) = lookup(material)             # [component+0x14b0] 的 vtable+0x60
    g = g_lo*(1-t) + g_hi*t                     # t = auth[component+0x934]
    g = g * auth[component+0x940]               # ← 车辆 tyre_force，来自 gdb idx78/79
    g = g * [component+0x121c]
    wheel+0xCC = g                              # 普通 float，非 auth
```

**要点：**

1. **那个 lerp 插的是路面材质的 low/high，不是车辆升级等级。**
   （早前判断有误，此处更正）
2. **车辆 tyre_force 是独立乘数**，与材质相乘而非插值。
3. **`wheel+0x1B8` 是接地判定，不接地则该轮抓地力完全不计算。**
   这是"损速判定依赖轮胎接地"的代码级证据。
4. `wheel+0xCC` 是计算结果，普通 float；`component+0x940` 是输入，auth float。两者不同层。

`wheel+0x1A4` 打包结构（`0x58684b4`）：

```
u32 → [7:0] 字段A | [15:8] 字段B | [31:16] 材质 index
```

## 4. 每帧力累加（`0x360dfe0`）

```
s0 = [component+0x271c]
if s0 == 0: return                  # 总开关，为 0 则整个函数不执行
for each wheel:
    ...
    s2 = [wheel+0xCC]               # 抓地力
    s2 = s17*(1-s1) + s1*s2         # s1 = [component+0x271c]
    v1.s[2] = s2
    v0 = [wheel+0x248] + v1
    [wheel+0x248] = v0              # vec4 累加器
    [wheel+0x258] = lerp(旧值, 新值, s1)
```

`wheel+0x238 / 0x248 / 0x258` 三者间隔 0x10，被同时取第 0 分量组成 3D 向量
（`0x5d2ca74` 一带），构成一个 **3×3 矩阵**——轮子局部坐标系。

## 6. 本轮更正的早期结论

| 早前说法 | 更正 |
|---|---|
| tyre 的 lerp 是"升级进度插值" | 实为**路面材质** low/high 插值 |
| `wheel+0xCC` 是 auth float | 是**普通 float**；auth 的是 `component+0x940` |
| `component+0x14b0` 查的是 CarPhysics 字段表 | 查的是**路面材质表** |
