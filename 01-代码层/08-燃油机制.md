# 燃油机制（游戏内部叫 Maintenance）

**第一个坑：搜 `fuel` 会被带偏。**
`fuel::` 是 Gameloft 后端框架的命名空间（`fuel::Connection` / `fuel::UserSession` /
`fuel::Matchmaking` / `fuel::PersistenceError`…），so 里 425 条相关串**全都跟车辆油量无关**。

车库里那个 `⛽ 6/6` 在代码里叫 **Maintenance（保养）**。

---

## 1. 数据结构：存在玩家档案里，不在 gdb 里

**gdb 里一个 `maintenance` 字符串都没有** —— 油量是**每辆车的存档状态**，
跟着玩家档案走，所以**服务端权威**。

每辆车记录里的油量块（结构取自服务端 `account_store.py` 的打包/解析代码）：

```c
u16  maintenanceSlots       // 当前油量槽
u64  refillEndTime          // 补充结束时间戳
u8   isRefilling            // 是否补充中
u16  slotsBeforeRefilling   // 开始补充前的槽数
u8   lastUsage              // 可选
u8   consecutiveDays        // 可选
u16  usageCounters[4]       // 使用统计
```

在车记录里的位置：`免费升级数组` 之后、`visualConfiguration` 之前。

## 2. 四个动作（客户端发 Request，服务端回 Result）

| 动作 | 作用 |
|---|---|
| `MaintenanceStartRefill` | 油量耗尽后启动补充计时 |
| `MaintenanceValidateRefill` | 计时到点后确认、回满 |
| `MaintenanceSkipRefillWithTokens` | 花代币立即补满 |
| `MaintenanceSkipRefillWithBonusPassBenefit` | 用通行证权益跳过 |

另有两条获取途径：`GetCarMaintenancefromAds`（看广告）、
`GetCarMaintenancefromMultiplayerPass`（多人通行证）。

## 3. 补充时长是服务端下发的，不是客户端常量

```
hasNextRefillTimePoint / nextRefillTimePoint
oldEndRefillTime / newEndRefillTime
```

客户端只负责显示倒计时（`refill_timer` / `zero_timer` / `refilling`），
**时间点由服务端算好推下来**。所以想改补充速度，只能改服务端。

## 4. 总槽数 = 基础 + 通行证加成

- UI 读 `current_maintenance` / `total_maintenance`
- `extraMaintenanceSlots` 出现在**赛季通行证结算载荷**里
- 文案佐证：
  - `STR_SEASON_PASS_BENEFITS_EXTRA_GAS_SLOTS`（额外油槽）
  - `STR_SEASON_PASS_BENEFITS_GAS_INSTANTLY_VIP_LEGEND`（立即加油）
  - `STR_SEASON_PASS_BENEFITS_TLE_EXTRA_REFILLS`（限时活动额外补充）

**基础槽数的来源还没定位** —— gdb 里没有，很可能是硬编码或服务端下发。
车主实机是 `6/6`。

## 5. 多人赛的"预订"机制

```
maintenanceBooking / maintenanceSlotsToValidate
MultiplayerSeriesMaintenanceBookingNotification
MultiplayerSeriesRequestRevertOfMaintenanceBooking
STR_MAINTENANCE_BOOKING_REVERTED
```

多人系列赛会**先预订**油量槽，比赛没成行则回滚预订。
所以 `slotsBeforeRefilling` 这个字段是为了回滚用的。

## 6. 其他相关

| 标识符 | 含义 |
|---|---|
| `low_gas` / `normal_gas` | UI 低油/正常两种显示态 |
| `maintenance_value_low` / `_normal` | 对应的数值样式 |
| `NotEnoughMaintenancePoints` | 油量不足的错误码 |
| `MaintenanceIsAlreadyFull` | 已满时重复补充的错误码 |
| `didMaintenanceFreeRefill` | 是否用过免费补充 |
| `isOutOfFuel` | **埋点字段**（重开练习赛时上报是否因没油） |
| `STR_NOTIFICATION_REFILLED_GAS_FOR_ALL_CARS_*` | 全车加满的推送通知 |
| `MaintenanceSkipPopup::k_showAdTimeout` / `k_checkAdTimeout` | 广告跳过的超时常量 |
| `STR_MAINTENANCE_POPUP_MSG_TEXT_REDUCED_CN` | **CN 版有单独的缩减文案**，时长可能与国际版不同 |

## 7. 可动的地方

**改 gdb 没用** —— 油量不在 gdb 里。

唯一入口是**服务端档案**：`server/server/account_store.py` 里
`GOLD_MAINTENANCE_SLOTS = 3`，各 class 的 gold profile 都写 3，
打包在 `struct.pack("<HQBH", slots, 0, 0, 0)`。

校验上限是 `0 <= slots <= 0xFFFF`。

> **注意**：车主实机显示 `6/6`，而档案写的是 3 ——
> 说明要么客户端/服务端在登录时补满过，要么 `maintenanceSlots` 不是"当前值"。
> **这一点没验证，改之前先确认语义。**
