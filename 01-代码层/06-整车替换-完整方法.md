# 整车替换：让 B 车彻底变成 A 车

**状态：已实测成功。** 科迈罗 LT ← 阿斯顿·马丁女武神，车库正常显示、可上车、不闪退。

```bash
python tools/carswap.py --from "Aston Martin Valkyre" --to "Chevrolet Camaro LT" --apply
./tools/build.sh camaro-v3 --tuned ".../tuned-carswap" --files CarPhysics.gdb CarChassis.gdb CarDef.gdb
```

一条命令，外观 + 物理 + 几何全换，只保留受体的身份。**全库覆盖率 99.0%。**

---

## 1. 三个库，三种手法

| 库 | 做什么 | 手法 |
|---|---|---|
| **CarPhysics** | 供体记录整体写进受体槽位，17 对 (低级值, 满级值) 全钉在满级端 | 记录体覆盖（等长）/ 整库重排（不等长） |
| **CarChassis** | 质量、轮距、轴距、轮径、重心全用供体的 | **一律复制记录体**（不用改指向，原因见 [07](07-底盘改指向的陷阱.md)） |
| **CarDef** | 供体整条车辆定义复制进受体槽位 | 整库重排 + 身份回填 |

**外观是 CarDef 带过来的。**
模型、贴图、碰撞、动画、特效、音效的引用全在 CarDef 里，
所以**不需要动任何资源文件，也不需要改 manifest 的 asset_id**。

## 2. CarDef 记录结构

```
+0   u64  身份       = 描述符 key 低 32 位 − 0x40000000
+8   u64  序号
+16  u32  名字长度
+20       名字 (ASCII)
          之后是 float 与一串 gdb key
```

替换时 **`+0` 与 `+8` 必须保留受体自己的**，`+16` 起全部取供体的。

### 记录内的 gdb key —— 必须全部回填

348/351 台车的 CarDef 恰好引用三条逐车记录：

| 所属库 | 含义 |
|---|---|
| `CarChassis.gdb` | 车身几何 |
| `CarPhysics.gdb` | 物理参数 |
| **`CarSounds.gdb`** | **引擎声** |

外加一个 `Global.gdb` 的共用 key（两车相同，不用动）。

> **只回填 physics / chassis 两个是不够的。**
> 漏掉 CarSounds 那个 key，游戏认不出这辆车 —— **车库里直接消失**。实测踩过。

按**所属库**配对（而不是按位置），同库多条按出现次序。
这样两车 key 数不同也能处理，覆盖率从 75.5% 提到 **99.0%**。

## 3. CarDef 变长了怎么办

科迈罗 2694B、女武神 2835B，替换后整库 +141B。

- **尾部依赖表安全**：CarDef 记录区之后有 376,612B 的依赖表，
  区内 47,076 个 u64 里**命中记录偏移的有 0 个**，全按 key 引用 —— 重排不影响它。
- **manifest 必须同步**：Pegasus manifest 里记着 `CarDef.gdb` 的明文大小 `C:5776600`，
  对不上游戏读不出来。`repack.py` 已自动改（位数相同才行，否则 manifest 行长会变）。

## 4. 走过的死路（别再试）

| 做法 | 结果 |
|---|---|
| 只换模型资源（改 manifest 的 asset_id） | **闪退** |
| 只换模型资源（直接覆盖资源字节） | **闪退**，堆栈逐帧相同 → 不是重复 asset_id 的问题 |
| 换成杰AB 做供体 | 照崩 → `carpaint02` 那条推断是错的 |
| 换成 Fordzilla P1（节点集是受体**严格子集**） | 照崩 → "子集才安全"也是错的 |
| 跳过 FX 三项资源 | 照崩 |
| CarDef 用 **alias**（受体描述符指向供体记录） | 不崩，但**两车共用一条定义、游戏按身份去重 → 受体消失** |
| CarDef **copy** 但只回填 physics/chassis | **受体消失**（漏了 CarSounds key） |
| CarDef **copy** + 回填全部逐车 key | **成功** |

**闪退的根因**（反汇编确认，不是猜的）：

```asm
36e2080: add  x1, x1, #0x8dc    ; 0x66ED8DC = "powderFactor"
36e209c: bl   0x4bff288         ; 查这个 shader 参数 -> 空 optional
...
4bfde7c: mov  w1, #0x23c        ; optional.inl 第 572 行
4bfde80: bl   assert_handler    ; "You are accessing an uninitialized optional!"
4bfde88: mov  x8, xzr
4bfde8c: mov  w9, #0xdead
4bfde90: str  w9, [x8]          ; *(0) = 0xDEAD ← 引擎主动断言自杀
```

外层是一个 for 循环：**遍历这台车的每个材质，挨个要 `powderFactor`**。
模型换了、CarDef 没换 → 配置与网格对不上 → 空 optional → 死。
**所以模型和 CarDef 必须一起换，这是硬约束。**

## 5. 验证方法（重要）

早期我用"进程还活着"判定成功，**两次都判错了** ——
游戏其实卡在「连接错误 1-2-5-2」弹窗上，一辆车都没加载。

`crashtest.sh` 是修正后的复现流程：

```
启动 -> 等 40s -> 点「重试」(1396, 935) -> 用 dumpsys exit-info 判定
```

- 判定看 `reason=5 (APP CRASH(NATIVE))`，**不看 logcat crash buffer**（会漏）
- 点「重试」能真正进主菜单，车库、收藏页、缩略图全都会加载
- **阴性对照已做**：纯物理版走同一路径不崩，所以这个复现是有区分度的
- 跑完自动 `am force-stop`，不让游戏一直挂着

## 6. 换完再微调

```bash
python tools/carswap.py     --swap "Aston Martin Valkyre>Chevrolet Camaro LT" --grip 0.95     --swap "Mercedes_AMG_One>BMW Z4 LCI E89"         --top-speed 285 --accel 2.932 --grip 1.0231 --cg -0.122 --nitro-drain 0.6     --apply
```

`--swap` 可重复，**每个微调参数作用于它前面最近的那个 `--swap`**，多台车互不影响。

| 参数 | 作用槽位 | 说明 |
|---|---|---|
| `--top-speed` | CarPhysics 22/23 | 物理极速 |
| `--accel` | 72/73 | 加速 |
| `--grip` | 78/79 | 抓地 |
| `--cg` | CarChassis 14 | 重心高（负值） |
| `--track-f` | CarChassis 4 | 前轮距 |
| `--nitro-drain` | 34/35, 42/43, 50/51, 58/59 | 四级氮气消耗倍率，<1 更省 |

**所有微调都同时写低级值和满级值**，否则会随星级插值。

**不动极速只提抓地是净赚**：

```
R = v² / a_lat      分母变大、分子不变 -> 半径变小
```

这正是 v2/v3 那批车"半径反而更大"的反面——那次是极速拉了 1.6 倍（v² 变 2.6 倍）
而抓地只翻倍，分子涨得更快。

**代价是抬轮**：`抬轮指数 = 抓地 × |重心高| ÷ 前轮距`，会同步上升。
女武神几何压得低（重心 −0.115、前轮距 1.626），所以有余量。

| 抓地 | 全库百分位 | 半径 | 抬轮指数 |
|---:|---:|---:|---:|
| 0.828（女武神原厂） | 75% | — | 0.0586 |
| **0.95（已装机）** | **89%** | **×0.87** | **0.0672** |
| 1.00 | 94% | ×0.83 | 0.0708 |
| 1.30（全库最高） | 100% | ×0.64 | 0.0920 |

全库抓地：最低 0.483 / 中位 0.777 / 最高 1.300（295 台）。
科迈罗原厂抬轮指数 0.0686 —— **0.95 这一档仍在它自己原来的水平之下**。
