# CarPhysics 运行时结构（已定）

来源：编译器生成的深拷贝函数 `0x3617aa8`，逐字段同偏移复制，结构一览无遗。

---

## 1. 布局

基址 = **`component + 0x358`**
（定基证据：`0x358 + 0x5E8 = 0x940`，实机 Frida 探针读 tyre_force 的偏移）

```
偏移      内容                         大小        字段数
+0x000   轮子 0                       0xCC = 204B  17 个 auth float
+0x0CC   轮子 1                       0xCC         17
+0x198   轮子 2                       0xCC         17
+0x264   轮子 3                       0xCC         17
+0x330   氮气组 0（单喷）              0x30 = 48B   4
+0x360   氮气组 1（橙喷）              0x30         4
+0x390   氮气组 2（蓝喷/完美）         0x30         4
+0x3C0   氮气组 3（紫喷）              0x30         4
+0x3F0   独立字段区，步长 0x0C 连续排布
   ...
+0x5E8   tyre_force  ← 独立区第 42 项，component 绝对偏移 0x940
```

### 结构证据

拷贝函数 `0x3617aa8` 的调用序列：

```
copy_wheel(+0x000)  copy_wheel(+0x0CC)  copy_wheel(+0x198)  copy_wheel(+0x264)
copy_nitro(+0x330)  copy_nitro(+0x360)  copy_nitro(+0x390)  copy_nitro(+0x3C0)
assign(+0x3F0)  assign(+0x3FC)  assign(+0x408)  ...
```

两个子结构拷贝函数都是定长循环，步长恰为 auth float 的 12 字节：

| 函数 | 循环上界 | 字段数 | 用途 |
|---|---|---:|---|
| `0x3617b3c` | `cmp x21, #0xCC` | **17** | 轮子 |
| `0x3617b74` | `cmp x21, #0x30` | **4** | 氮气组 |

```asm
0x3617b74:  x21 = 0
loop:       assign(x20+x21, x19+x21)     ; bl 0x35854f4
            x21 += 0xC
            cmp x21, #0x30 ; b.ne loop
```

## 2. 与 gdb 的映射规则

**每个 gdb 的 `(low, high)` 对 → 运行时 1 个 auth float**（经升级进度 lerp 后写入）。

氮气部分**已闭合**，gdb 每组 8 个 float = 4 对，运行时每组 4 个 auth float，顺序一致：

| gdb 槽位 | 含义 | 运行时偏移（组基址 + ） |
|---|---|---|
| (base+0, base+1) | A（未解） | +0x00 |
| (base+2, base+3) | drain 消耗 | +0x0C |
| (base+4, base+5) | spd 速度加成 | +0x18 |
| (base+6, base+7) | 维持能力 | +0x24 |

组基址：gdb idx 32 / 40 / 48 / 56 → 运行时 +0x330 / +0x360 / +0x390 / +0x3C0

## 3. auth float 是一个 C++ 类

有完整的运算符封装，地址经参数传递（这是早前追不到偏移的原因）：

| 地址 | 运算 |
|---|---|
| `0x35854f4` | `operator=`（decode 源 → encode 目标） |
| `0x3546d30` | `operator/` |
| `0x3546d70` | `operator*`（auth × 普通 float） |
| `0x354bfd8` | `operator-` |
| `0x3535a04` | 置零 |

`operator=` 有 **72 个调用点**，其中 `0x3617xxx` 一片是结构拷贝。

## 4. 尚未闭合

- **轮子 17 个字段各是什么**——已知每轮有 spring / dampingCompression / dampingRebound
  （运行时实测报告佐证），但 17 项的完整顺序未定。
- **独立字段区的排列**——已知第 42 项是 tyre_force，其余未定。
- **填充这个结构的代码**——拷贝函数是编译器 out-of-line 副本（无 RELA、无调用者），
  真正从 gdb 读值并 lerp 写入的函数还没定位。物理区内无 `#0x1AC`(428) 常量，
  说明记录不是按整块尺寸搬运的。

> 注：`0x3617aa8` / `0x3617b3c` / `0x3617b74` 三者均无调用者也无 vtable 引用，
> 是编译器为内联函数生成的 out-of-line 副本。**但它们照真实结构生成，布局有效。**

## 6. 首条完整闭合的映射：氮气

| | gdb | 运行时 |
|---|---|---|
| 结构 | 4 组 × 8 float = **16 对** | 4 组 × 4 auth float = **16 个** |
| 组基址 | idx 32 / 40 / 48 / 56 | +0x330 / +0x360 / +0x390 / +0x3C0 |
| 组内顺序 | A, drain, spd, 维持 | +0x00, +0x0C, +0x18, +0x24 |

**数量与顺序双向吻合，映射闭合。**

## 7. 数量核对与推论

| | 数量 |
|---|---:|
| gdb 检出的对 | 34 |
| 运行时字段（轮子区） | 68（4 × 17） |
| 运行时字段（氮气区） | 16 |
| 运行时字段（独立区，至少到 tyre） | 43+ |

**34 对 ≪ 127+ 个运行时字段**，所以：

1. **4 个轮子共享同一组 gdb 参数**，运行时展开成 4 份（否则 gdb 需要 68 对）
2. **相当一部分运行时字段不来自 gdb**，是默认值或派生量
   （与"44 个 gdb 槽是全车常量"相符——那些是引擎默认值）

## 9. 速度上限：600 km/h 的真相

**静态二进制里 `166.667`（= 600 km/h）只出现一次**，位于 `0x65f56ac`，
被 `0x356a970` 以 `lerp([x1+4], 166.667, [x0+0x1ec]/100)` 使用。
但该函数挂在一张**跳转表分发的条件检查**上（返回 bool），
**是任务/条件系统的参数，不是物理速度 cap。**

真正的上限在**运行时结构**里：

```
speedAnchor + 0xC4 = reference
speedAnchor + 0xC8 = limitA
speedAnchor + 0xCC = limitB
```

`speedAnchor` 由内存特征 `ae ca 61 3f`(0x3F61CAAE) 扫描定位，**静态二进制中无此结构**。

> 项目早期脚本 `frida_senna_speed_540_watchdog.js` 的注释已记载：
> *"The game's separate 600 km/h airborne cap is deliberately left untouched."*
> 即：改动只把两份 ground-speed 设为 120 m/s (432 km/h)，
> **600 km/h 的空中上限从未被修改，一直是游戏原生值。**

## 10. 转向系统：预计算速度曲线表

`0x35cd070` 一带构建一张 **30 点速度曲线表**：

```
s9  = 2.77778   (10 km/h)
s10 = 138.889   (500 km/h)
for i in 0..29:
    t     = i / 29.0
    speed = lerp(10km/h, 500km/h, t)
    u     = clamp((speed - lo) / (hi - lo), 0, 1)
    R     = lerp(R_lo, R_hi, u)
    (sin, cos) = sincos(angle)        # bl 0x344f300
    ω     = -(base + speed*sin * speed*cos * (-2) / R)
```

**该表只覆盖到 500 km/h。** 超过 500 km/h 后转向参数将停在表尾，
不再随速度变化——这对超出原厂速度区间的车辆（如改动后的塞纳）
是一个已知的行为边界。

## 12. 驱动力施加（`0x360bbe0`）

```
if (!接地(wheels[0]) || !接地(wheels[1])):  return     # 驱动轮都必须接地
torque = [component+0xC94] * 0.5 * auth_decode(x19)
force  = torque / wheel.radius                          # [wheel+0x20]
wheel[+0x240] += force
```

**要点：驱动力只在驱动轮接地时施加**——四轮腾空时没有驱动力输入。
`component+0xC94` 是发动机扭矩来源。

## 13. 接地判定的使用广度

`0x584bb74`（读 `wheel+0x120+0x98`）共 **26 个调用点 + 4 个尾调用**，
遍布抓地力计算、驱动力施加、接触处理、每帧力累加等。
**"接地"是整个物理层的总闸门。**
