# 拼装式调参的四个副作用（车主实测）

v2/v3 那批改造车（三菱 / Z4 / 370Z）实测反馈：

> "都有共同点，台轮很高，半径很大，而且极速都差不多一样，
> 而且氮气条中间有蓝条很小"

四条全部指向同一个根因：**把各车的最优值拼在一起，不等于一台好车。**

---

## 1. 台轮很高

抬轮指数 = 抓地 × \|重心高\| ÷ 前轮距。

我把抓地统一拉到全库顶层（1.153），**几何一个字节没动**。
分子暴涨、分母不变 → 抬轮必然跟着翻倍。Z4 从 0.0631 涨到 0.1255，
**超过全车原厂上限 0.1216**。

原厂车不会这样，是因为高抓地车同时配了低重心和宽轮距。**拆开抄就露馅。**

## 2. 半径很大 ← 最有价值的一条

这条推翻了我原来的理解。我把 `idx77` 拉满 1.00、转向锐度拉到 56500，
**半径反而更大**。

原因是过弯半径不由操控字段单独决定：

```
R = v² / a_lat
```

极速拉了 1.6 倍 → `v²` 变成 **2.6 倍**；抓地只涨到约 2 倍。
分子涨得比分母快，**半径必然变大**。

**结论：极速和半径是绑死的。**
只加操控不压极速，半径一定退步——这正是原厂"要操控就得让极速"
（`idx76/77` 与极速相关 −0.49 / −0.52）的设计意图。
我当时把这条相关性当成"取舍"记下来了，却没意识到它在改装时会反噬。

## 3. 极速都差不多一样

方案里四台车填了同一个目标值。**这是设计缺陷不是 bug** ——
把每台车都推到同一个上限，车与车的性格就被抹平了。

## 4. 氮气蓝条很小

蓝条 = 完美氮气（蓝喷）的触发窗口。
我从 Chiron 抄加成、从 Agera RS 抄消耗、从 Devel 抄维持——**三台不同的车**。
窗口宽度显然与这几项存在联动，拼出来的组合落在了窗口极窄的区域。

**具体是哪个槽控制窗口宽度，目前未定位。** 待查。

---

## 教训

**逐字段抄最优值 = 造出一台不存在的车。**
原厂每台车的 107 个槽是一整套互相咬合的配平，
抓地配几何、极速配操控、氮气三项配窗口。

**整车移植（`transplant.py`）没有这个问题**——
搬过来的是一整套原厂配平，内部必然自洽。
